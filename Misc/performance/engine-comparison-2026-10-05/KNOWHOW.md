# Benchmark know-how

What we learned building and running the six-engine benchmarks (QSS-M, Ironwail,
vkQuake, QSS, FTEQW, ezQuake) on Windows 11 / RTX 4070 / NVIDIA 610.88,
October 5-6 2026. Read this before re-running anything here.

## Fairness rules we settled on

- One owned process per pass, fresh config, 800x600 window (physical client size checked), VSync and MSAA off, uncapped, sound on. One discarded warm-up, then five measured passes in rotating engine order.
- `sys_throttle 0`/`-1` for every engine that has it. Ironwail and vkQuake still sleep 16 ms/frame when unfocused even in demos, so the runner foregrounds the window (`focusutil.py`, `AttachThreadInput`) and rejects any ~60 FPS pass as focus-throttled (kept under `excluded_samples`).
- Player demos run QSS-M with `scr_autoid 0`. `gl_powerupshells` was tested and has no measurable effect.
- Configs go in a pak named with the next consecutive number (pak2 in id1, pak3 in ad): classic engines stop at the first missing pakN.
- FTE needs `-noupdates` (its update prompt otherwise stalls the run). ezQuake can't join NetQuake servers and is not ranked on connection times.

## Engine quirks that bite the harness

- vkQuake writes its `-condebug` log to the real `%APPDATA%\vkQuake\qconsole.log`, not the basedir.
- Ironwail mirrors the console to `stdout.log`; parse each log separately and use unique per-run markers.
- QSS-M `wait` advances on the 72 Hz tick, so chained timedemos in one cfg cut long demos short. Run one demo per process.
- Quake caps the command line at 50 args; long `+wait` chains silently drop later commands.
- First run after a while is cold OS cache (file lookups up to 5x slower). Use medians, always warm up.

## What the numbers mean

- **NVIDIA threaded optimisation**: the GL driver runs single-threaded for ~2 s after rendering starts, then switches with a one-time 60-80 ms stall. Fresh-process timedemos run entirely before the switch, so they understate warmed FPS. Warmed QSS-M Aerowalk is ~3,100 FPS, matching live play.
- Any GL call that returns a value (`glGenTextures`, `glGenBuffers`) forces a driver sync. That's why QSS-M now pools texture and buffer names.
- The windowed present floor is ~190 µs/frame for every engine (SDL2 or SDL3; see `swaptest`). Above ~3,000 FPS, everything else is small.
- QSS-M's immediate-mode HUD costs ~26 µs/frame. Batching 2D drawing is the largest known FPS win left. Heavy maps (ad_tears) and the CTF demo are where QSS-M still trails Ironwail/QSS.
- Before the fix, QSS-M loaded demo precaches inside timed frames (QSS deferred precache). That cost 26-33% of fresh-process timedemo FPS.

## Map-load findings

- Timing comes from `developer 1` console lines written with `-condebug`.
- Wins, in order of size: load-scoped missing-directory cache, parallel image decode with item colours computed on the worker, pooled GL names, signon messages handled between server ticks (no physics/QC/time), PACK sounds kept across maps.
- Rejected (data in `ab-results/` and `rejected-loadsync-and-probes.patch`): `GL_DEBUG_OUTPUT_SYNCHRONOUS` at startup (removes the first-load stall but locks the driver single-threaded, -5-9% FPS); toggling it only during loads (slower); full extra server frames during signon (replaced by message-only steps after review).
- Edge cases the review found are all covered by `Misc/stress/test_*.py`: sound slot reuse, changed or loose sound files, audio-rate changes, `host_framerate` during signon, directories created mid-load (including from other threads), and `vid_restart` keeping or resetting name pools.

## Practical tips

- Build: `harness/map-load-final/build.sh <name>` (MSBuild x64 Release). Tests: `run-tests.cmd <test.py...>` from a vcvars shell.
- Editing CRLF C files from Python heredocs kept turning `"\n"` into real newlines. Use an editor or byte-exact replacement (`sub.py`).
- Map-load runs write `id1/saves/autosave/*.sav` into the game dir; clean them up.
- Test-build zips are gitignored. Rebuild from the commit the report names.
