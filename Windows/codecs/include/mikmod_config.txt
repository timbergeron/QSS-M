The toolchain's static runtime plus -static-libgcc avoids shared GCC or

Windows PowerShell recipe, from a separate build directory next to the
extracted libmikmod-3.3.15 source. Extract w64devkit to
%TEMP%/qssm-deps/toolchain/w64devkit. Use a short, space-free absolute toolchain
path (the refresh host's %TEMP% is a short path). If %TEMP% contains spaces,
choose another space-free extraction path for $bin.

$bin = "$env:TEMP/qssm-deps/toolchain/w64devkit/bin".Replace([char]92, [char]47)
$env:PATH = $bin.Substring(2)
$env:CC = "$bin/gcc.exe"; $env:LD = "$bin/ld.exe"
$env:CONFIG_SHELL = "$bin/sh.exe"; $env:SHELL = "$bin/sh.exe"
$env:AWK='awk'; $env:GREP='grep'; $env:EGREP='grep -E'; $env:FGREP='grep -F'; $env:SED='sed'
$env:AR='ar'; $env:RANLIB='ranlib'; $env:STRIP='strip'; $env:DLLTOOL='dlltool'; $env:OBJDUMP='objdump'; $env:NM='nm'
$env:lt_cv_deplibs_check_method='pass_all'; $env:lt_cv_prog_gnu_ld='yes'
& "$bin/sh.exe" ../libmikmod-3.3.15/configure --build=i686-w64-mingw32 --host=i686-w64-mingw32 --enable-shared --disable-static --disable-sdl --disable-xaudio2 --disable-openal 'LDFLAGS=-static-libgcc -Wl,--no-insert-timestamp'
& "$bin/make.exe" -j4
& "$bin/i686-w64-mingw32-strip.exe" --strip-unneeded .libs/libmikmod-3.dll

PATH above omits the drive prefix because BusyBox's POSIX PATH uses colon
separators; it still resolves to the toolchain on the current drive. Explicit
Unix utility variables avoid BusyBox/Autoconf tool-discovery failures.
Explicit short-path CC/LD, the w64devkit shell and lt_cv_prog_gnu_ld=yes keep
libtool on its GNU linker path. The original auto-detected LD path contained
spaces; configure invokes $LD -v unquoted, so the GNU linker probe failed
and generated an invalid MSVC-style gcc ... -link -dll command.
No manual link or generated-libtool patch is needed.

Copy .libs/libmikmod-3.dll into Windows/codecs/x86/. The public mikmod.h
header comes from the MSYS2 x64 package. Both DLLs retain all 172 old exports,
so the existing import libraries remain usable. Both import only KERNEL32,
msvcrt, DSOUND, WINMM, ole32 and USER32; no new runtime DLL is needed.
